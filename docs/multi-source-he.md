# ארכיטקטורת Multi-Source

המערכת אינה תלויה בלוח יחיד. כל מקור עובר דרך Adapter שמייצר רשומה אחידה, ולאחר מכן אותה שרשרת מטפלת בהיסטוריית מחיר, ניתוח, ציון והתראות.

## מצב החיבורים

| מקור | מצב | דרך איסוף | הערה |
|---|---|---|---|
| יד2 | פעיל | Apify, `crawloop~yad2-scraper` | תומך Monitor Mode |
| מדלן | פעיל | Apify, `swerve~madlan-scraper` | קלט לפי עיר ו-`dealType` |
| הומלס | פעיל | Apify, `swerve~homeless-scraper` | `enrichListings` מופעל לקבלת שטח ומאפיינים |
| Komo | פעיל | איסוף HTML ישיר | האתר מחזיר כרטיסי מודעות בצד השרת, ללא צורך בדפדפן מלא |
| ad.co.il | פעיל | איסוף HTML ישיר | מסומן כמאגד כדי למנוע ספירה כפולה כראיה עצמאית |
| Facebook Marketplace | קליטה ידנית | Inbox בדשבורד | קישור, פרטים וצילום מסך אופציונלי, ללא סריקה אוטומטית |
| רשות המסים | ייבוא ראיות | JSON מתוך מקור מורשה | עסקאות נשמרות בנפרד ממודעות ומשפיעות על השווי רק לאחר התאמה |
| GovMap | אימות גאוגרפי | API ראיות וקישור רשמי | קואורדינטות, גוש וחלקה נשמרים עם מקור ורמת ביטחון |
| OnMap | מוכן לחיבור | טרם נבחר מחבר יציב | אינו נסרק ואינו נספר בכיסוי |

## איחוד מודעות

אותו נכס מאוחד אוטומטית ברמת `property_id` רק כאשר יש התאמה חזקה:

1. עיר, רחוב ומספר בית זהים לאחר נרמול, או
2. קואורדינטות זהות בקירוב של 5 ספרות עשרוניות.

כאשר מספר הבית חסר, המערכת לא מאחדת אוטומטית על סמך שם רחוב בלבד. מנוע ההתאמה מחשב ציון לפי עיר, רחוב, שכונה, חדרים, שטח, קומה, מחיר, מספר קשר ותמונה ראשית. התוצאה נשמרת כאחת משלוש רמות: `possible`, `probable`, או `confirmed`.

```text
GET /api/v1/listings/:id/cross-source-candidates
```

החלטה זו מעדיפה כפילות זמנית על פני חיבור שגוי של שתי דירות שונות באותו רחוב.

## הפעלה

המקורות הפעילים נקבעים ב-`.env`:

```text
ENABLED_SOURCES=yad2,madlan,homeless,komo,ad
SCAN_CITIES=קריית אונו,גני תקווה,אור יהודה,יהוד מונוסון
```

אותו `APIFY_TOKEN` משמש את יד2, מדלן והומלס. Komo ו־ad.co.il נאספים ישירות ולכן אינם צורכים קריאת Apify. כל Actor עשוי להיות מחויב בנפרד לפי התמחור שלו.

רק התאמה בסטטוס `confirmed`, או זהות מלאה של `property_id`, מאוחדת בתצוגת הדשבורד. התאמות `probable` נשארות נפרדות כדי לצמצם איחודים שגויים.

סריקה מלאה:

```bash
npm run scan
```

סריקת מקור יחיד דרך API:

```bash
curl -X POST http://localhost:3000/api/v1/ingest/apify \
  -H 'content-type: application/json' \
  -d '{"source":"madlan","type":"sale","maxItems":50}'
```

כשל במקור אחד נשמר ב-`source_scan_runs` ואינו מוחק נתונים קיימים. אם לפחות מקור אחד הצליח, הריצה מוחזרת כ-`partial: true` במקום לאבד את כל תוצאת הסריקה.

## הערכת שווי מבוססת ראיות

כאשר קיימות עסקאות אמת מתאימות בחמש השנים האחרונות, המערכת מסננת לפי עיר, חדרים ושטח, מעדיפה אותו רחוב ואותה שכונה, ומחשבת טווח שווי לפי רבעון תחתון, חציון ורבעון עליון של המחיר למ״ר. מספר העסקאות ושיטת החישוב מוצגים בניתוח הנכס. אין ערבוב בין מחיר מודעה למחיר עסקה.

OCR של Marketplace מתבצע בדפדפן באמצעות Tesseract בעברית ובאנגלית. התוצאה אינה ראיה מאומתת: המשתמש רואה את השדות שחולצו ומאשר אותם לפני הקליטה.
